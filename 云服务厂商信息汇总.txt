腾讯云 SMS 服务 · 配置与操作记录
================================

【2026-11-18 更新】下面是查证腾讯云官方文档后的版本。
上一版有两处是错的，已更正 —— 别再照着旧说法配模板。

────────────────────────────────────────
一、已确定的值
────────────────────────────────────────

应用列表：

1. 梦之城综合门户
   SDKAppID: 1401230486     ← SMS_APP_ID 就是它

签名（已有两条，类型不同，不能混用）：

  · 「营销」签名 —— 已审核通过
      只能配「推广短信」模板 → 不能发验证码
  · 「验证码」签名 —— 报备中（待审核）
      只能配「验证码短信」模板 → 这才是发验证码要用的

────────────────────────────────────────
二、腾讯云的三条硬规则（踩过才知道）
────────────────────────────────────────

1. 签名类型必须与模板类型一致
   验证码签名 ↔ 验证码短信模板
   通用签名   ↔ 通知短信模板
   营销签名   ↔ 推广短信模板
   类型不匹配 = 发不出去，报
   FailedOperation.SignatureIncorrectOrUnapproved
   或 TemplateIncorrectOrUnapproved

2. 模板参数个数必须与模板变量个数一致
   · 验证码类模板通常只有 1 个变量：{1} 是验证码，
     有效期写死在文案里（例：「您的验证码是{1}，5分钟内有效」）
   · 通用/通知类模板可以有 2 个：{1} 验证码、{2} 有效期
   参数个数由环境变量 SMS_TEMPLATE_PARAM_COUNT 控制（默认 1）

   ⚠ 上一版这里写的「必须带两个参数」是错的 ——
     那是因为代码当时把 TemplateParamSet 写死成了 [code, '5']。

3. 返回体有两层错误，只看一层会漏
   · 顶层 Response.Error（密钥错、模板不存在、签名没审过）
     → SDK 会抛异常
   · 每个号码的发送状态 SendStatusSet[].Code（限流、模板不符等）
     → SDK 不抛，必须自己看
   代码已修：两层都查，失败就返回 502 并在日志里记下腾讯云错误码，
   不再出现「短信没发出去但前端显示已发送」。

────────────────────────────────────────
三、还需要你去腾讯云控制台做的
────────────────────────────────────────

A. 等「验证码」签名审核通过（现在报备中）
   腾讯云 → 短信 → 签名管理 → 看状态

B. 建一个「验证码短信」类型的模板（1 个参数）
   腾讯云 → 短信 → 模板管理 → 添加模板
   类型：验证码短信
   内容：您的验证码是{1}，5分钟内有效。
   （有效期 5 分钟要和 SMS_CODE_TTL_MINUTES 一致）

   ⚠ 通用类模板也能配 2 个参数，但那种模板发验证码
     审核时可能被驳回（用途属于登录/注册验证码）。
     首选验证码类模板 + 1 个参数。

C. 建 CAM 子账号拿密钥（别用主账号密钥）
   腾讯云 → 访问管理 → API 密钥管理 → 新建子账号
   权限只给 QcloudSMSFullAccess（或更细的自定义策略）
   拿到 SecretId / SecretKey

D. 如果一个教室的家长共用一个公网 IP
   腾讯云同一 IP 的限制是每分钟 100 条 —— 我们代码里 300 条/小时
   远在它之内，不需要在腾讯云做任何调整。
   真要调高是走工单：
   腾讯云控制台右上角 → 工单 → 说明业务用途与峰值 QPS。

   （我们自己的 IP 闸门在 SMS_IP_HOURLY_LIMIT，默认 300/小时，
     够一整个学校用。）

────────────────────────────────────────
四、填到哪里（你自己在终端跑，密钥不过工具）
────────────────────────────────────────

服务器 /home/ubuntu/dreamcity-platform/.env（不是 GitHub Secrets ——
部署链路是 git archive → 服务器 docker compose --env-file .env，
.env 从不上 GitHub）：

  ssh tencent "cd /home/ubuntu/dreamcity-platform && cat >> .env <<'EOF'
  SMS_DRIVER=tencent
  SMS_APP_ID=1401230486
  SMS_SECRET_ID=AKIDxxxx
  SMS_SECRET_KEY=xxxx
  SMS_SIGN_NAME=<验证码签名的内容>
  SMS_TEMPLATE_CODE=<验证码模板的 ID>
  SMS_TEMPLATE_PARAM_COUNT=1
  SMS_CODE_TTL_MINUTES=5
  EOF"

然后重启 app 容器：
  ssh tencent "cd /home/ubuntu/dreamcity-platform && sudo docker compose --env-file .env -f deploy/docker-compose.yml up -d"

验收：
  curl.exe https://platform.lhdreamcity.com/api/health
  然后在家长端用真手机号点「获取验证码」，看短信到不到。
  日志里有失败原因（含腾讯云错误码）：
  ssh tencent "docker logs --tail 50 dreamcity-platform"

────────────────────────────────────────
五、测试阶段（签名还没下来时）
────────────────────────────────────────

「营销」签名已通过，可以拿它先把整条链路跑通 ——
但必须配「推广短信」类型的模板（2 个参数也行），
因为营销签名只能配推广模板。

⚠ 推广短信有额外的合规要求（腾讯云要单独开通推广短信权限），
  而且拿推广模板发验证码内容属于「用推广短信干验证码的活」，
  只适合本地/测试环境验证链路，别带到生产。

本机验证（不用等签名）：
  设好上面的 SMS_* 环境变量后：
    SMS_DRIVER=tencent
    npm run start
  然后 POST /api/auth/guardian/send-code
  失败会在服务端日志里打印腾讯云错误码，能直接看出是签名问题还是密钥问题。
