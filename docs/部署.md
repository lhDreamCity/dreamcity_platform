## 1. 一次部署

```bash
# 拉代码
git clone <repo> /opt/dreamcity && cd /opt/dreamcity

# 装依赖（生产也要装 devDependencies，因为 tsx 跑 TypeScript）
npm ci

# 打包前端
npm run build

# 建库 + 灌 48 节课（只灌内容，不要演示数据）
npm run db:migrate
npm run seed:content    # ⚠️ 生产不要跑 npm run seed（会建公开的演示账号）

# 起服务
npm start
```

`npm start` 跑的是 `tsx src/server.ts`。服务端会：

1. **自检生产配置** —— 缺 `JWT_SECRET` / `DATABASE_URL` / `REDIS_URL` / `CORS_ORIGINS`
   直接拒绝启动，不会带着默认密钥上线
2. 托管 `packages/web/dist`（前端）与 `activities/`（活动插件）
3. 其余路径按 SPA 路由回落到 `index.html`

**端口**：默认 8787，只监听 `0.0.0.0`，前面放 Nginx。

## 2. 环境变量（生产）

```bash
NODE_ENV=production
SERVER_PORT=8787

# 域名与跨域：必填，否则启动失败
CORS_ORIGINS=https://learn.你的域名.com,https://www.你的域名.com

# 数据库：必填
DATABASE_DRIVER=pg
DATABASE_URL=postgres://user:pass@host:5432/dreamcity

# 缓存：必填（课堂码与限流要跨进程共享）
REDIS_URL=redis://127.0.0.1:6379

# 令牌：必填，至少 32 位
JWT_SECRET=<openssl rand -hex 32>
TOKEN_TTL_MINUTES=720

# 短信
SMS_DRIVER=tencent
SMS_APP_ID=1400xxxxxx
SMS_SECRET_ID=AKIDxxxx
SMS_SECRET_KEY=xxxx        # 注意：代码从 SMS_SECRET_KEY 读
SMS_SIGN_NAME=梦之城
SMS_TEMPLATE_CODE=xxxxx

# 对象存储（腾讯云 COS，走 S3 兼容协议）
OBJECT_STORE_DRIVER=s3
S3_ENDPOINT=https://cos.ap-guangzhou.myqcloud.com
S3_REGION=ap-guangzhou
S3_BUCKET=dreamcity-1250000000
S3_ACCESS_KEY_ID=AKIDxxxx
S3_SECRET_ACCESS_KEY=xxxx
S3_PUBLIC_BASE_URL=https://dreamcity-1250000000.cos.ap-guangzhou.myqcloud.com
```

启动自检会逐条告诉你缺什么：

```
生产环境配置不完整，拒绝启动：
  · JWT_SECRET 太短（至少 32 位）
  · 生产环境必须设置 CORS_ORIGINS（否则任何站点都能调接口）
```

## 3. Nginx

```nginx
server {
    listen 80;
    server_name learn.你的域名.com;
    # 证书申请之后改成 301 跳转
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name learn.你的域名.com;

    ssl_certificate     /etc/letsencrypt/live/learn.你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/learn.你的域名.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_session_cache shared:SSL:10m;

    # 平台是封闭域，作品与课件都不该被搜索引擎收录
    add_header X-Robots-Tag "noindex, nofollow, noarchive" always;

    # 上传大小：作品照片与任务单
    client_max_body_size 20m;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    location / {
        proxy_pass         http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # 活动插件：直接静态托管，缓存久一点（内容带版本号）
    location /activities/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        expires 7d;
    }

    # 打包后的静态资源带 hash，可以长期缓存
    location /assets/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

> **前端托管位置有两种选法**：
> - **A（默认）**：后端托管 `packages/web/dist`，Nginx 只做透传 —— 上面这份配置即可
> - **B**：Nginx 直接托管 `packages/web/dist`，后端只管 `/api` —— 更省一点应用服务器资源，
>   但要自己写 SPA 回落：`try_files $uri $uri/ /index.html;`

## 4. systemd

`/etc/systemd/system/dreamcity.service`：

```ini
[Unit]
Description=梦之城综合教学平台
After=network.target postgresql.service redis-server.service

[Service]
Type=simple
User=dreamcity
WorkingDirectory=/opt/dreamcity
EnvironmentFile=/opt/dreamcity/.env
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=5

# 优雅关闭：给 20 秒处理完在跑的请求
KillSignal=SIGTERM
TimeoutStopSec=20

# 基本加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/opt/dreamcity/var

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dreamcity
sudo journalctl -u dreamcity -f
```

应用收到 `SIGTERM` 会先停止接受新请求、等在跑的请求做完、再断开数据库与缓存连接。

## 8. 出问题时先看哪里

| 现象 | 先查 |
|---|---|
| 家长登不上 | Redis 是否活着（验证码与令牌都在缓存里）；`CORS_ORIGINS` 是否包含实际域名 |
| 学生进不去 | 课堂码是否过期（2 小时）或已结课；缓存是否活着 |
| 插件不出现 | `activities/` 目录是否在部署包里；插件 manifest 是否注册 |
| 页面 404 | 前端 dist 是否构建；`SERVE_WEB` 是否被设成 `false` |
| 502 | 后端进程是否活着：`systemctl status dreamcity` |
| 作品看不到 | 该件的 `visibility` 与 `visibility_grant` 是否匹配（越权一律 404） |

| 项 | 值 |
|---|---|
| 域名 | `https://platform.lhdreamcity.com` |
| 主机 | 193.112.18.222（Ubuntu 22.04，2C / 3.7GB） |
| 入口 | Caddy（`workbench-deploy-caddy-1`）→ `dreamcity-platform:8787` |
| 栈 | `dreamcity-platform`（app）+ `-db`（postgres:16）+ `-redis`（redis:7） |
| 代码目录 | `/home/ubuntu/dreamcity-platform` |
| 部署脚本 | `bash deploy.sh`（build → up → 等健康 → 自检） |
| 数据 | Docker 卷 `dreamcity-platform_db-data` / `_redis-data` / `_objects` |
| 证书 | Caddy 自动签发 Let's Encrypt |

同机的 `lhdreamcity.com`（官网）与 `work.lhdreamcity.com`（workbench）**不受影响**，
平台只是 Caddyfile 里新增了一个站点块。

### 10.1 ⚠️ Caddyfile 是单文件 bind mount —— 一个会咬人的坑

`/home/ubuntu/workbench-deploy/Caddyfile` 以**单文件**方式挂进容器：

```
/home/ubuntu/workbench-deploy/Caddyfile//deleted → /etc/caddy/Caddyfile (ro)
```

这意味着：

1. **容器里的文件是只读的**，改不动
2. **如果用会替换文件的方式改主机上的 Caddyfile**（`mv`、写临时文件再改名、
   某些编辑器保存方式），容器仍绑在**已删除的旧 inode** 上 —— 配置改了半天**完全不生效**，
   而且 `caddy reload` 读到的还是旧版
3. 容器里看到的字节数与主机上的对不上，就是这个症状

**正确的改法**：

```bash
# 追加（tee -a 保持 inode 不变）
sudo tee -a /home/ubuntu/workbench-deploy/Caddyfile > /dev/null <<'EOF'

platform.lhdreamcity.com {
    reverse_proxy dreamcity-platform:8787
}
EOF

# 热加载（零停机）
sudo cat /home/ubuntu/workbench-deploy/Caddyfile | \
  sudo docker exec -i workbench-deploy-caddy-1 caddy reload --config - --adapter caddyfile
```

改完**核对两边内容一致**：

```bash
sudo md5sum /home/ubuntu/workbench-deploy/Caddyfile
sudo docker exec workbench-deploy-caddy-1 md5sum /etc/caddy/Caddyfile
```

如果两边哈希不同（说明主机文件被替换过），执行一次
`sudo docker restart workbench-deploy-caddy-1` 让 Docker 重新绑定到当前 inode。
**重启会让另外两个站点抖 1–2 秒**，挑个合适的时机做。

### 10.2 建讲师账号（生产必须自己跑）

生产不灌演示数据，所以要手动建一个讲师账号：

```bash
ssh tencent
sudo docker exec dreamcity-platform /app/node_modules/.bin/tsx \
  /app/packages/seed/src/create-teacher.ts \
  --email 你的邮箱 --name "你的名字" --role TEACHER
```

密码随机生成，**只打印这一次**，请立刻保存。
（这个步骤由人执行：密码不该经过任何会记录它的工具。）

### 10.3 当前生产配置的两处妥协

启动时应用会打印警告，是有意为之，不是 bug：

| 项 | 当前值 | 影响 | 何时该改 |
|---|---|---|---|
| `SMS_DRIVER` | `log` | 家长验证码只打到服务端日志，**真实家长登不进来** | 拿到腾讯云短信 AppID / SecretId / 签名 / 模板 ID 后改 `.env` 并 `docker compose up -d app` |
| `OBJECT_STORE_DRIVER` | `local` | 作品与课件存在容器卷里，单机够用 | 换机器或加实例前要接腾讯云 COS，补 `S3_*` 环境变量 |

改 `.env` 后的重启方式：

```bash
cd /home/ubuntu/dreamcity-platform
sudo docker compose -p dreamcity-platform \
  --env-file /home/ubuntu/dreamcity-platform/.env \
  -f /home/ubuntu/dreamcity-platform/deploy/docker-compose.yml \
  up -d app
```

### 10.4 定期回滚 / 更新

```bash
cd /home/ubuntu/dreamcity-platform
# 备份数据库
sudo docker exec dreamcity-platform-db pg_dump -U dreamcity -d dreamcity \
  | gzip > ~/dreamcity-platform-$(date +%Y%m%d).sql.gz

# 更新代码 → 重建 → 滚动
bash deploy.sh
```

`deploy.sh` 只重建 app 容器，db / redis 不动，数据不丢。

### 10.5 排查

| 现象 | 先查 |
|---|---|
| 域名打不开 | `sudo docker ps` 看容器是否在；`sudo docker logs --tail 50 dreamcity-platform` |
| HTTPS 报错 | Caddy 是否拿到证书：`sudo docker logs workbench-deploy-caddy-1 \| grep acme` |
| 改了 Caddyfile 没生效 | 见 10.1 —— 多半是 inode 问题 |
| 登录不上 | `SMS_DRIVER=log` 时验证码在 `docker logs dreamcity-platform` 里 |
| 数据库连不上 | `sudo docker exec dreamcity-platform-db pg_isready -U dreamcity` |
