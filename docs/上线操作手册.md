# 上线操作手册（对着做）

> **给谁看**：想把梦之城平台从「本地能跑」变成「线上真的能用」的人。
>
> **怎么用**：从上往下做，一步不落。每步都写了**在哪台机器跑**、**在哪个目录**、
> **期望看到什么**、**失败了怎么办**。卡住了看「三、卡住了怎么办」。
>
> **当前状态**：线上还是 11 月 6 号那版（旧代码）。本次要做的把它换成新版本，
> 并让家长端能真收到短信验证码。
>
> ⚠️ **全程在你自己电脑的普通 PowerShell 里操作，不要在 AI 对话里跑。**
> 原因：私钥和口令不该经过任何会记录它们的工具。

## 一、把仓库改成私有（1 分钟）

> **为什么**：仓库现在 public，里面的域名、部署脚本、基础设施细节全网可见。
> 短信密钥虽然已排除在外，但私有更稳妥。

**在哪跑**：浏览器。

1. 打开 <https://github.com/lhDreamCity/dreamcity_platform/settings>
2. 滚到最下面 **Danger Zone**
3. 找到 **Change visibility** → 点 **Change visibility**
4. 选 **Private** → 按提示输入仓库名 `dreamcity_platform` 确认
5. 可能会要求输入密码或 2FA 验证

**期望看到**：仓库标题旁边出现 `Private` 标记。

**注意**：改完之后，`docs/` 里那几段「用匿名 API 看 CI 状态」的脚本会失效（返回 404）——
那是正常的，已经换成 `tools/ci-status.mjs`（见第五步）。

## 二、登录 GitHub CLI（1 分钟）

> **为什么**：后面填 GitHub Secrets、改仓库设置都要用 `gh`。
> 登录一次就长期有效。

**在哪跑**：**本机**（你的电脑），普通 PowerShell。

```powershell
gh auth login --hostname github.com --git-protocol ssh --web
```

**会发生什么**：终端显示一串**设备码**（像 `XXXX-XXXX`）和一个网址。
→ 把设备码填进浏览器 → 授权 → 回到终端。

**期望看到**：`✓ Logged in as lhDreamCity`。

**如果 `gh` 找不到**：用全路径

```powershell
& "C:\Users\admin\.claude\tools\gh\bin\bin\gh.exe" auth login --hostname github.com --git-protocol ssh --web
```

## 三、跑一键初始化脚本（5 分钟）

> **这一步做完，GitHub 才连得上服务器。** 现在 Deploy 每次都失败，就是因为这一步
> 从没跑过：4 个 GitHub Secrets 没配，服务器上也没有部署脚本。

**在哪跑**：**本机**，普通 PowerShell。

```powershell
powershell -ExecutionPolicy Bypass -File D:\dreamcity_platform\tools\setup-ci-deploy.ps1
```

**脚本做四件事**（都可重复跑，做过的会自动跳过）：

| # | 做什么 | 成功长什么样 |
|---|---|---|
| 1 | `ci-deploy.sh` 上服务器并加执行权限 | `✓ ci-deploy.sh 就位` |
| 2 | 生成 CI 专用部署密钥，写进服务器 `authorized_keys`（带 forced command，这把钥匙除了部署什么都干不了） | `✓ authorized_keys 已写入` |
| 3 | 服务器自己随机生成 `ADMIN_PASSWORD` 写进 `.env`（不经你的电脑） | `✓ 已写入` |
| 4 | 填 4 项 GitHub Secrets | `✓ 4 项 Secret 都填好了` |

**期望看到**（最后一行）：

```
✓ 初始化完成
```

**可能卡住的地方**：

| 现象 | 怎么办 |
|---|---|
| 卡在「gh 需要登录」 | 说明第二步没做完，回去做 |
| `scp 失败` | 先确认 `ssh tencent` 能通 |
| `本机 known_hosts 里没找到 193.112.18.222` | 先跑一次 `ssh tencent` 接受主机指纹，再重跑脚本 |

## 四、把短信配置写进服务器（2 分钟）

> 服务器上的 `.env` 是真正生效的地方。密钥只放这里，**不进仓库**。

**在哪跑**：**本机**，普通 PowerShell。

```powershell
ssh tencent "cd /home/ubuntu/dreamcity-platform && sed -i '/^[[:space:]]*SMS_/d' .env && cat >> .env <<'EOF'
SMS_DRIVER=tencent
SMS_APP_ID=1401230486
SMS_SECRET_ID=<你的子用户 SecretId>
SMS_SECRET_KEY=<你的子用户 SecretKey>
SMS_SIGN_NAME=深圳领航梦之城科技
SMS_TEMPLATE_CODE=2761496
SMS_TEMPLATE_PARAM_COUNT=2
SMS_CODE_TTL_MINUTES=5
EOF"
```

**SecretId / SecretKey 从哪拿**：你本地的 `D:\dreamcity_platform\云服务厂商信息汇总.txt`
里有（文件末尾「4. 子用户」那一段）。

> ⚠️ **`sed -i` 那行别删**。它先清掉旧的 `SMS_` 行再写新的。
> 少了这一步，`.env` 里会有两份同名变量，后面的覆盖前面的 →
> 「我改了怎么没生效」。部署前的检查也会拦这种重复，但那时已经晚了。

**写完自检**（服务器上跑，Node 在）：

```powershell
ssh tencent "cd /home/ubuntu/dreamcity-platform && node deploy/check-env.mjs .env"
```

**期望看到**：`✓ .env 配置检查通过（/home/ubuntu/dreamcity-platform/.env）`

> 如果报「缺少 SMS_SECRET_KEY」之类，说明上面那条命令没写进去，重做这一步。
> 如果报「出现了多次」，说明 `.env` 里有重复的 `SMS_*` 行，`sed -i` 那行没生效。

## 六、验收（3 分钟）

**在哪跑**：**本机**，普通 PowerShell。

```powershell
# 1. 健康检查 —— 期望 {"ok":true,...}
curl.exe https://platform.lhdreamcity.com/api/health

# 2. 讲师后台入口还在 —— 期望 200
curl.exe -o NUL -w "%{http_code}" https://platform.lhdreamcity.com/console

# 3. 3D 插件这次应该在了（11-06 那版是 404）—— 期望 200
curl.exe -o NUL -w "%{http_code}" https://platform.lhdreamcity.com/activities/var-lab-3d.html

# 4. 落地页只有家长与学生两个入口，没有讲师入口 —— 期望：搜不到任何指向后台的链接
curl.exe https://platform.lhdreamcity.com/ | Select-String -Pattern "console|讲师"
```

**再人工开一次浏览器**：

- 落地页只有「家长」「学生」两个入口；
- `/console` 能用正式讲师账号登进去；
- 插件库 4 个（柠檬摊、提示词 quests、变量实验室 2D、变量实验室 3D）；
- **用真手机号在家长端点「获取验证码」，看短信到不到** ← 这是本次的重点

**短信到不了就看日志**：

```powershell
ssh tencent "docker logs --tail 50 dreamcity-platform | grep 短信发送失败"
```

对照错误码：

| 错误码 | 意思 | 怎么办 |
|---|---|---|
| `AuthFailure.SecretIdNotFound` | SecretId 不存在或写错 | 核对第四步填的值 |
| `AuthFailure.SignatureFailure` | SecretKey 不对 | 核对第四步填的值 |
| `FailedOperation.SignatureIncorrectOrUnapproved` | 签名没审过 / 类型和模板不匹配 | 签名内容要填「深圳领航梦之城科技」 |
| `FailedOperation.TemplateIncorrectOrUnapproved` | 模板不存在或没审过 / 不属于这个应用 | 模板 ID `2761496` |
| `FailedOperation.TemplateParameterError` | 模板参数个数不对 | 本项目模板是 2 个变量，`SMS_TEMPLATE_PARAM_COUNT=2` |
| `LimitExceeded.PhoneNumberDailyLimit` | 该号码当天发太多 | 腾讯云默认 300 条/天 |

## 七、（可选）建正式讲师账号

后台占位账号 `admin` 是应急用的。正式账号在服务器上建，**口令只在你自己的终端里出现一次**：

```powershell
ssh tencent "cd /home/ubuntu/dreamcity-platform && npm run create:teacher --email <你的邮箱> --name <你的名字>"
```

建完有两种选择：

- **保留占位账号**：方便应急，但 `admin` 这个名字会一直存在；
- **关掉占位账号**：在服务器 `.env` 加一行 `ADMIN_ENABLED=false`，重启 app 容器后占位账号被删。

> 建议保留到第一次真实上课跑通之后再关。

## 三、卡住了怎么办

### Deploy 一直失败

先看是哪一步：

```powershell
node D:\dreamcity_platform\tools\ci-status.mjs --jobs
```

| 失败的步骤 | 原因 | 怎么办 |
|---|---|---|
| 「传到服务器并部署」 | 第四步（初始化脚本）没跑成功 | 重跑第三步 |
| 「线上验收」 | 镜像重建失败或起不来 | `ssh tencent "docker logs --tail 60 dreamcity-platform"` |
| 「打包」 | 极少见的 git 问题 | 重推一次 |

### 服务器 `.env` 配错了想重来

```powershell
# 看现在有什么（密钥会被显示出来 —— 只在你自己屏幕上）
ssh tencent "grep SMS_ /home/ubuntu/dreamcity-platform/.env"
```

改完记得重启 app 容器：

```powershell
ssh tencent "cd /home/ubuntu/dreamcity-platform && sudo docker compose --env-file .env -f deploy/docker-compose.yml up -d app"
```

### 一切正常，想回滚

Actions 里选一个旧的提交 → Deploy → Run workflow，代码就回到那一版。
数据库在独立 volume 里，回滚代码不动数据。
