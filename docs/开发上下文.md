## 1. 我们在为什么做

线下中小学 AI 应用与基础商业思维辅导机构，深圳南山，约 280㎡。
服务对象 **3–9 年级**学生，付费方是家长。

经营范围是「业务培训（不含许可类教育培训）+ 教育咨询」，所以：

> **合规口径：所有对外表述走「AI 素养 / 科技素养」，避开学科类培训表述。**
> 这一条会传导到前端文案、页面标题、分享卡片、页脚。

### 溢价从哪来

| 项 | 值 |
|---|---|
| 标准报价 | 600 元/h = 900 元/节（1 节 = 1.5h） |
| 折扣价 | 480 元/h = 720 元/节 |
| 班型 | **≥2 人小班**（下限已定） |
| 师资 | 创始人亲自带课 |
| 单次时长 | 90 分钟 |

> **⚠️ 口径修订**：班型基线已从「1 对 1 / 1 对 3 精品班」改为 **≥2 人小班**，
> **720 元/节所依赖的前提随之失效，须按小班人头重新定价**。这是业务侧待办，
> **代码里不得沿用旧价、也不得自行推算新价** —— `enrollment.price` 存 `NULL`。

**溢价来自 M5 个别点拨与 M6 对外输出里的真人追问，以及「陪伴」关系。
不是来自课件，不是来自平台功能，更不是来自录播内容。**

由此推出一条贯穿全平台的红线：

> **平台一旦把主线做成录播 / 在线课，定价与「陪伴」定位会同时失守。**
> 平台要做的是让线下 90 分钟跑得更顺，并把课堂自动沉淀成资产 —— 不是替代课堂。

### 双主线

市面同类多为纯 AI 通识课。我们的定位是 **AI 应用线 × 商业思维线**：

- 每期第 8 节产出 AI 作品，第 16 节做真实商业实战（市集 / 路演）
- 每节课细案都有「双主线连接」字段，说明这课怎么把两条线接上
- 家长看得见的是「孩子做出了什么、讲得清什么」，不是「学了几个工具」

## 2. 术语表（强制使用）

| 术语 | 定义 | 别混淆 |
|---|---|---|
| `lesson` | **教案模板**，一节课的设计（如 `L1-04`），会修订版本 | 不是「一次上课」 |
| `class_session` | **一次真实上课**，指向当时 `lesson` 的版本快照 | 必须与 `lesson` 拆表 |
| `term` | 期次（一个班从开课到结业） | 不是年级，不是课程级别 |
| `activity` | 一个可独立运行的互动课件 / 游戏 | 本项目里课堂编排那张表叫 `session_activity` |
| `activity_plugin` | 插件注册表里的一个活动 | 与 `session_activity` 不同 |
| `showcase` | 学生「被看见」的展位条目 | 不是 `artifact`，一件作品可由多个结果组成 |
| `A1–A8` | 交互原子（谁握控制权 × 信息往哪流） | 不是课堂模式 |
| `M1–M6` | 模式卡（按课型把原子装配进 90 分钟） | **M5 / M6 必须真人** |
| `GRADE_L1/L2/L3` | **课程级别**：启蒙 3–4 / 进阶 5–6 / 实战 7–9 | ⚠️ 见 2.2 |
| `VIS_L0..L3` | **可见范围**：私密 / 本班 / 跨期 / 对外 | ⚠️ 见 2.2 |
| 课堂码 | 6 位、当堂有效、下课失效的**会话凭证** | **不是学生账号**，不产生长期身份 |
| 宿主 (host) | 拉起活动并接收 `postMessage` 的讲师驾驶舱页面 | — |

### 2.2 ⚠️ 命名陷阱

历史文档里同时存在两套 `L` 编号：

| 前缀 | 含义 | 取值 |
|---|---|---|
| `GRADE_L1` / `GRADE_L2` / `GRADE_L3` | 课程级别（按年级段） | 3 级 |
| `VIS_L0` / `VIS_L1` / `VIS_L2` / `VIS_L3` | 作品可见范围 | 4 级 |

**代码里禁止出现裸的 `L1` / `L2` / `L3`。** 数据库字段、枚举、常量、API 参数、
前端文案变量一律使用带前缀的形式。这是本项目最可能出错的一处，
已有文档里存在混用，**以本表为准**。

自动化检查：`npm run check:constraints` 的 **N1** 项。

## 3. 谁在用，什么时候用

| 角色 | 主要诉求 | 设备 | 第一优先级 |
|---|---|---|---|
| 讲师（创始人 / 助教） | 90 分钟课堂不卡壳、不用课后补录 | 教室 PC / 投屏机 | **操作效率** |
| 学生 | 做作品、被同伴与家长看见、带走成果 | 投屏 / 家庭手机 | **情绪价值、无挫败** |
| 家长 | 看见过程与进阶、决定续费 | 手机 | **可信、可读、克制** |
| 教研 | 修订细案、看哪节课卡了 | PC | **版本与数据可追溯** |
| 管理员 | 排课、课消、账号、授权、合规审计 | PC | **可控、可撤回** |

### 场景约束（决定了很多技术选择）

| 场景 | 特征 | 对实现的约束 |
|---|---|---|
| 备课 | 网络正常 | 能预览活动、查看细案版本 |
| **课堂 90 分钟** | 投屏机可能**老旧集显、被 IT 关硬件加速、全班共用一块屏、无键盘供学生登录**；教室网络可能不稳 | **离线可用、零外部请求、无 WebGL 时自动降级 2D、课堂上不要求登录** |
| 课后家庭 | 手机，碎片时间 | 学生端轻量、无需记密码、加载快 |
| 结业 | 导出可带走的电子作品集 | 导出成文件，不依赖平台在线 |
| 招生 | 展示经授权的作品 | 逐件授权 + 水印 + 可撤回 |

> **一个反复被验证的结论：教室网络与投屏机，比 GPU 更可能毁掉一节课。**
> 因此「设备确定性 > 性能上限」「离线优先」「零外部请求」是硬约束，不是优化项。

## 4. 教学流程

### 4.1 课程结构

| 级别 | 年级 | 节数 | 教学特征 |
|---|---|---|---|
| `GRADE_L1` 启蒙级 | 3–4 | 16 × 1.5h | 无公式、全体验，每节有纸面产出带回家 |
| `GRADE_L2` 进阶级 | 5–6 | 16 × 1.5h | 固定/变动成本、盈亏平衡、≥10 份真实访谈 |
| `GRADE_L3` 实战级 | 7–9 | 16 × 1.5h | 大模型幻觉、Python、智能体、相关≠因果；**明确允许并鼓励推翻自己的假设** |

共 **48 节**，每节细案统一 10 个字段。已全量入库（`content/lessons.json`）。

### 4.2 90 分钟五环节

```
导入 → 讲解 → 实操 → 展示 → 收尾
```

- 讲授 **≤25 分钟**；其余时间孩子动手
- 每 **12–15 分钟切换一次交互原子**
- **每节必有 M6（对外输出）**，10–15 分钟展示环节
- 平台的时间轴自动记录环节实耗，**不要让讲师填表**

> 细案里 L1-16 与 L2-16（结业日 / 路演日）原文就是 100 分钟，不是 90。
> 平台按每节课自己的 `canonicalMinutes` 排时间轴，不硬套 90。

### 4.3 交互原子与模式卡

设计变量只有两个：**谁握控制权**（讲师 / 学生 / 工具 / 外部对象）、
**信息往哪流**（一对多 / 一对一 / 多对多 / 人机 / 对外）。

| 代号 | 含义 |
|---|---|
| A1 | 讲师一对多讲演 |
| A2 | 学生自行使用 PC 钻研 |
| A3 | 讲师与全场互动 / 游戏 |
| A4 | 学生间互动 / 游戏 |
| A5 | 讲师与单个学生互动 |
| A6 | **学生对外输出**（家长可见成果、续费依据、传播素材的唯一来源） |
| A7 | **AI / 平台作为第三角色**（AI-native 机构的分水岭） |
| A8 | **外部真实对象**（家长当顾客、嘉宾当评委） |

| 模式卡 | 用途 |
|---|---|
| M1 讲授锚定 / M2 人机钻研 / M3 全场共振 / M4 同伴协作 / M5 个别点拨 / M6 对外输出 | 每张卡带**失效信号**；按课型给配方，如概念课 `M3→M1→M2+M5→M6→M1` |

**两条不可违反的教学红线：**

> - **M5、M6 必须真人。** 未来 AI 最多替代 M1 和部分 M2。这正是**溢价**与「陪伴」的实质。
> - **课件会被抄，编排抄不走。** 模式库同时决定助教培训 SOP、平台功能优先级、
>   以及 AI 能替代哪一段。因此「模式卡序列」必须是一等数据，不是 PPT 备注里的文字。

### 4.4 班型下限与设备基线（已拍板）

> **决策**：首期正式班型规模因尚未招生仍待定，但**下限已确定为 ≥2 人小班；
> 不设计 1 对 1，也不为该边界状态做任何适配或兜底**。首次试课样本为
> **2 名 4 年级（GRADE_L1）学生，一人一机**。
>
> **设备**：**一人一机是设计基线**。PC 数量不足时**优先租更多 PC**，
> 而不是退化为共享机或轮换上机。

由此产生的直接结论：

- **A4（学生间互动）在 ≥2 人小班下成立**，48 节细案无需改写
- 平台**不要**试图用功能「自动适配」班型。
  `class_session.participant_count` 按 **≥2** 校验（数据库 CHECK 约束）
- 方法论修正：把「待定」拆成「**已定下限 + 待定规模**」，
  而不是让整项待定阻塞全部下游设计

> 连带待办（业务侧，非平台侧）：按 ≥2 人小班重定报价；场地与助教配置重算。
> **Agent 不得自行填数字。**

## 5. 三个前端入口，一台后端

| 名称 | 本质 | 有状态 | 身份 | 网络 |
|---|---|---|---|---|
| **教学互动平台**（活动运行时） | **无状态的活动运行时 / 活动库** | ❌ | ❌ 不碰身份 | 可完全离线、零外部请求 |
| **综合管理平台** | **有状态的系统（Classroom OS）** | ✅ | ✅ 权威源 | 需要网络（课堂端要能断网降级） |

```
后端（唯一数据与身份权威）
  ├─ 入口 1 · 讲师驾驶舱   备课 · 时间轴 · 拉起活动 · 看结果
  ├─ 入口 2 · 家长/学生端   作品展位 · 三类句式留言 · 成长档案 · 导出
  └─ 入口 3 · 活动运行时    宿主页面 → iframe 活动（postMessage 回传，不直连后端）
```

**关键边界：**

- **活动永远不直连后端。** 结果通过 `postMessage` 交给宿主，由宿主落库；
  断网时宿主本地缓存，恢复后补传。
- **学生账号与「被看见」的全部数据属于后端。**
- **教学互动平台完全不知道「现在是谁在玩」。**
  课堂只需要 6 位课堂码这种当堂失效的会话凭证。

### 5.1 为什么「被看见」不放进课堂投屏端

课堂里的即时反馈（结算画面、徽章、连击）由活动自己给，那是**即时成就感**；
「被看见」是**跨时间的社会性反馈**，不必也不该在课堂现场完成。

课后落库 → 孩子回家用手机看 → 家长跟着看。**这反而把课堂延伸进了家庭，是设计优势。**

## 6. 「被看见」体系

### 6.1 它为什么不是「附加的社交功能」

```
做作品 → 以自己名义展示 → 被同伴 / 家长 / 往期学员看见并回应
      → 形成「我做得不错」的自我认知 → 才愿意做下一个
```

这条链断了，M6 就只剩「下课前轮流念一遍」。
商业上也成立：**作品展位是唯一能让孩子主动带家长回来看的东西**。

历史教训：早期方案为了「合规省事」写成「学生无账号、课后会话失效、不留历史」，
等于把自己刚补上的 A6 与 C2（跨期异步互评作品墙）角色又删了。**那是工程视角，不是教育视角。**

### 6.2 四级可见范围 `VIS_L0..L3`

| 层级 | 谁能看 | 默认 | 用途 | 授权方式 |
|---|---|---|---|---|
| `VIS_L0` 私密 | 本人 / 讲师 / 家长 | ✅ | 草稿、失败尝试、测评原始分 | 无需授权 |
| `VIS_L1` 本班 | 同期班学员与家长 | 需勾选 | 同伴互评 A4、当期作品墙 | 报名时一次授权 |
| `VIS_L2` 跨期 | 本校区在读与结业学员 | 二次授权 | 异步互评，补「同伴」角色 | 家长单独同意 |
| `VIS_L3` 对外 | 公开链接 / 海报 | 逐件授权 | 招生、家长转发、转介绍 | 逐件、带水印、可撤回 |

> **合规判断**：《未成年人网络保护条例》并不禁止未成年人拥有账号，
> 约束的是无监护人同意、无边界、非最小化的处理。
> **封闭域反而是合规最优解** —— 数据不出机构、访问者全是同机构学员与家长、
> 无公开索引、监护人全量可见可撤回。

### 6.3 六项机制

1. **人人有展位**，按时间排序、不按优劣
2. 头像装备随 `GRADE_L1 → GRADE_L2 → GRADE_L3` 升级
3. 跨期留言**只准三类句式**：「我注意到…」/「我喜欢…」/「我想问…」
4. 孩子能看到「谁看过、留了什么话」，但**不显示任何数字**
5. 结业导出**可带走**的电子作品集
6. 账号**不因结业注销**

### 6.4 七条风险对策

无开放注册与公开索引 ｜ 外链逐件授权带水印 ｜ 昵称制，不采集位置与设备指纹 ｜
无信息流、无推送 ｜ 家长可看全部动态与每条留言 ｜ 可导出 ｜ 可注销

### 6.5 ⛔ 明确禁止清单

**不做：私信、关注、点赞计数、人气榜、公开检索、无限信息流、任何形式的量化人气指标。**

理由不是合规，是 `GRADE_L1` 第 16 节细案特意写了「**不以营收排名，按敢讲、算得清、会复盘结业**」：

> 一旦有量化人气指标，孩子会迅速学会做「容易获赞」的作品，而不是做自己真正想做的。

**这是「有围墙的身份」和「社交产品」的分水岭。**
数据模型里禁止出现 `like_count` / `view_count` / `rank` 之类的字段，哪怕备注写「以后可能用」。

## 7. 可量化验收指标

| 指标 | 目标 | 怎么验 |
|---|---|---|
| 讲师单节录入操作 | **≤3 次点击** | `check:constraints` C6 + 课堂实跑 |
| 活动首屏 | < 2s | 实机 |
| 活动外部网络请求数 | **0** | `check:constraints` C3 |
| 断网场景 | 活动仍可完成，结果本地缓存，恢复后补传 | 需实机演练 |
| 无 WebGL 设备 | 自动降级 2D，教学流程不中断 | `check:constraints` C4 + 实机 |
| 可见性越权 | 服务端 100% 拦截，返回 404 | `smoke-test.mjs` |
| 学生端人气数字 | **0 个** | `check:constraints` C8 |
| 家长操作 | 可导出全部数据、可撤回授权、可注销 | `smoke-test.mjs` |
| 每次 `class_session` | 指向当时 `lesson` 的版本快照 | `check:constraints` C5 |

### 什么算失败（反指标）

- 讲师觉得「还不如用 PPT + 微信群」→ 平台被弃用，**这是最大的失败**
- 孩子开始挑「容易获赞」的作品做 → 机制与课程价值观打架
- 课堂上因为登录 / 网络 / WebGL 卡住超过 1 分钟 → 90 分钟的课被毁
- 改一次细案，往期课堂记录对不上
- 平台出现录播 / 在线课主线 → 定价与「陪伴」定位同时失守

## 8. 硬约束（不可违反，每条都有自动化检查）

| # | 约束 | 来源 |
|---|---|---|
| C1 | 对外文案只用「AI 素养 / 科技素养」，不写学科培训类表述 | 经营范围 |
| C2 | 不做录播 / 直播课主线；V3 的 AI 最多替 M1 和部分 M2，M5/M6 必须真人 | 定价与陪伴定位 |
| C3 | 活动为**单文件 HTML、零外部 CDN、零后端请求**，支持 `offline_fallback` | 教室网络 / 投屏机 |
| C4 | 无 WebGL 时自动降级 2D，复用同一套场景状态与教学逻辑 | 投屏机硬件 |
| C5 | `lesson` 与 `class_session` 必须拆表，后者存版本快照 | 细案会迭代 |
| C6 | 讲师单节录入 ≤3 次点击；时间轴自动算实耗 | 平台会被弃用的头号原因 |
| C7 | 可见范围在**服务端强制过滤**；越权返回 404 | 未成年人数据 |
| C8 | 禁止任何量化人气指标与相关字段 | 课程价值观 |
| C9 | 课堂码是会话凭证，不产生长期身份；活动不持有身份 | 架构边界 |
| C10 | 所有 `VIS_L2` / `VIS_L3` 授权逐件可撤回；外链带水印 | 合规 |
| C11 | 家长可导出全量数据、可注销；数据不出机构、无公开索引 | 合规 |
| C12 | 错误反馈不用红叉；儿童产品只给正向引导 | 年龄适配 |
| C13 | 未定稿的商业数据留占位，不编造 | 真实性 |

映射表见 `docs/硬约束检查清单.md`。

## 9. 与其他系统的边界

### 9.1 教学互动平台（活动运行时）

- 定位：**替代 PPT 的课堂投屏互动**
- 形态：一批独立单文件 HTML 活动 + 一个宿主页面
- **不持有账号、不持有身份、不直连后端**
- 课堂用 6 位课堂码进入，当堂有效、下课失效
- 3D 技术基线：Three.js 锁 **WebGL2**（不是 WebGPU 优先）；单文件、外部请求 0；
  无 WebGL 时降级 2D Canvas 顶视图

### 9.2 活动插件规范

```
活动 = 独立 HTML + manifest + postMessage 结果回传
```

- `manifest` 声明 `activity_id`、名称、适用 `GRADE_L*`、时长、`result_schema`、
  `offline_fallback`
- 结果消息：`{ type: 'dreamcity:activity:result', activityId, sessionId, payload, visibility, ts }`
- 单文件、零 CDN、零后端请求
- 教研以后加课眼不用等研发排期

详见 `docs/插件规范.md`。

### 9.3 明确不属于本平台

课程细案的编写与修订、PPT 内容生产、3D 活动的画面与玩法实现、
招生页面、支付（V1 不做在线支付）。
