## 1. 第一步：把本地提交推上 GitHub

CI 与 Deploy 都由 GitHub 触发，代码必须先到 GitHub。

```powershell

git commit -m "chore: 加上部署通道一键初始化脚本"
git push github main
```

> 期望看到 `main -> main`。如果报 `everything up-to-date` 说明早就推上去了，跳过。

## 3. 第三步：跑初始化脚本（核心一步）

```powershell
powershell -ExecutionPolicy Bypass -File D:\dreamcity_platform\tools\setup-ci-deploy.ps1
```

脚本做四件事，每件都幂等 —— 重复跑不会出事，做过的会跳过：

| # | 做什么 | 成功长什么样 |
|---|---|---|
| 1 | `ci-deploy.sh` 上服务器并加执行权限 | `✓ ci-deploy.sh 就位` |
| 2 | 生成 CI 专用密钥，写进服务器 `authorized_keys`（带 forced command） | `✓ authorized_keys 已写入（备份在 authorized_keys.bak.<时间戳>）` |
| 3 | 服务器 `.env` 补 `ADMIN_PASSWORD`（**服务器自己随机生成**，不经本机） | `✓ 已写入` 或 `✓ 已存在，不动` |
| 4 | 填 4 项 GitHub Secrets | `✓ 4 项 Secret 都填好了` |

**跑之前可能卡一下**：脚本检测到 gh 没登录，会给你一个设备码，
在浏览器里输入确认即可。之后再跑一次或让它继续。

**可能卡住的地方**：

- `ssh-keygen -F` 找不到主机密钥 → 先手动 `ssh tencent` 连一次（接受指纹），
  脚本重跑就会拿到 `DEPLOY_KNOWN_HOSTS`。
- `scp` 失败 → 先确认 `ssh tencent` 能通。

跑完最后会打印下一步该做什么。

> 🔑 这把 CI 密钥是**只读身份**：服务器 `authorized_keys` 里挂的是
> `command="/home/ubuntu/ci-deploy.sh"`，所以这把钥匙除了「收代码包并部署」什么都干不了。
> 私钥只存在你本机 `~/.ssh/id_ed25519_deploy_ci`，GitHub 那边只存它作为 Secret。

## 4. 第四步：触发一次 CI + Deploy

Secrets 配好后，**推一次提交**就会自动触发 CI，CI 绿了 Deploy 接着跑：

```powershell
git commit --allow-empty -m "chore: 触发部署"
git push github main
```

也可以在 GitHub 网页上：Actions → CI → Run workflow。

**看跑到哪一步了**（匿名 API 就能读，不用等日志）：

```powershell
$h=@{'User-Agent'='ps'}
$run=(Invoke-RestMethod "https://api.github.com/repos/lhDreamCity/dreamcity_platform/actions/runs?per_page=5" -Headers $h).workflow_runs
$run | Select-Object name,status,conclusion,head_sha
$ci = $run | Where-Object { $_.name -eq 'CI' } | Select-Object -First 1
$jobs=(Invoke-RestMethod "https://api.github.com/repos/lhDreamCity/dreamcity_platform/actions/runs/$($ci.id)/jobs" -Headers $h).jobs
$jobs | ForEach-Object { "$($_.name) => $($_.conclusion)"; $_.steps | ForEach-Object { "   $($_.name) => $($_.conclusion)" } }
```

> 注意用 `curl.exe` 而不是 `curl` —— PowerShell 5.1 里 `curl` 是 `Invoke-WebRequest` 的别名，
> 接不了 `-o` / `-w` 这两个参数。下面所有 curl 都写成了 `curl.exe`。

期望：

```
CI     => success
Deploy => success
```

Deploy 的步骤依次是：打包 → 传到服务器并部署 → 线上验收。
**「传到服务器并部署」**那步内部会做：收 tar 包 → 校验 → rsync 到
`/home/ubuntu/dreamcity-platform` → `docker compose up -d --build` → 轮询健康检查。
整个过程约 3–5 分钟（要重建镜像）。

## 6. 第六步：正式讲师账号

后台占位账号是应急用的。正式讲师账号在服务器上建，**口令只在你自己的终端里出现一次**：

```powershell
ssh tencent "cd /home/ubuntu/dreamcity-platform && npm run create:teacher --email <你的邮箱> --name <你的名字>"
```

建完之后有两个选择：

- **保留占位账号**：方便应急，但 `admin` 这个账号名会一直存在；
- **关掉占位账号**：在服务器 `.env` 里加一行 `ADMIN_ENABLED=false`，重启 app 容器后占位账号被删。

> 建议保留到第一次真实上课跑通之后再关。

后台占位账号的口令（`ADMIN_PASSWORD`）在服务器 `.env` 里，要看的话：

```powershell
ssh tencent "grep ADMIN_PASSWORD /home/ubuntu/dreamcity-platform/.env"
```

## 7. 出问题了先看哪里

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| CI 的「冒烟」job 挂在 `npm run build` | 又踩了 `NODE_ENV=production` 让 `npm ci` 跳过 devDependencies | 检查 `.github/workflows/ci.yml` 里 job 级有没有 `NODE_ENV` |
| Deploy 挂在「传到服务器并部署」 | Secrets 没配 / 密钥不匹配 / 服务器 `.env` 缺项 | 脚本第 4 步；服务器日志：`ssh tencent "cat /home/ubuntu/dreamcity-platform/deploy.log"`（若有） |
| Deploy 挂在「线上验收」 | 镜像重建失败或起不来 | `ssh tencent "docker logs --tail 60 dreamcity-platform"` |
| 服务器连不上（runner 在美国） | 网络抖动 | 重跑一次 Deploy；反复失败就换近一点的 runner |
| `docker compose` 报 `ADMIN_PASSWORD 必须设置` | 服务器 `.env` 没这一项 | 脚本第 3 步 |

**回滚**：Actions 里选一个旧的提交 → Deploy → Run workflow，代码就回到那一版。
数据库在独立 volume 里，回滚代码不动数据。

## 8. 走这条通道之后，不用再做的事

- ❌ 不用再 `tar` 打包再 `scp` 到服务器
- ❌ 不用手动 `docker compose up -d --build`
- ❌ 不用重跑 `npm run db:migrate`（容器 entrypoint 每次启动都会跑迁移 + 灌 48 节课内容，幂等）
- ❌ 不用动同机的官网（`lhdreamcity.com`）与 workbench（`work.lhdreamcity.com`）

## 9. 一个待拍板的事：仓库要不要改成私有

`lhDreamCity/dreamcity_platform` 现在是 **Public**（建仓时设的），所以匿名 API 就能读到
Actions 的状态与结论 —— 上面第 4 步那段脚本就是这么用的。

代码里没有密钥，但写着生产域名、部署脚本与基础设施细节。

改成 Private：仓库 → Settings → General → Danger Zone → Change visibility。
**代价**：第 4 步那段匿名读结论的脚本会 404，要给 `gh` 配好登录再读：

```powershell
$h=@{'User-Agent'='ps';'Authorization'="Bearer $((& gh auth token) -join '')"}
```

不改也行 —— 这是你的仓库，你决定。
