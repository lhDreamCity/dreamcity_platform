> 2. 你本地的 `云服务厂商信息汇总.txt`（该文件已在 `.gitignore` 里，仓库是 public，绝不能推上去）

## 一、腾讯云的三条硬规则

踩过才知道，写在最前面：

### 1. 签名类型必须与模板类型一致

| 签名类型 | 只能配 |
|---|---|
| 验证码 | 验证码短信模板 |
| 通用 | 通知短信模板 |
| 营销 | 推广短信模板 |

类型不匹配 → 拒发，报 `FailedOperation.SignatureIncorrectOrUnapproved`
或 `FailedOperation.TemplateIncorrectOrUnapproved`。

> ⚠️ 本项目的「营销」签名虽然已审核通过，但**它配不了验证码模板**。
> 发验证码必须用「验证码」签名配「验证码短信」模板。

### 2. 模板参数个数必须等于模板变量个数

- 验证码类模板通常只有 **1 个**变量（`{1}` 是验证码，有效期写死在文案里）
- 通用/通知类模板可以有 **2 个**（`{1}` 验证码、`{2}` 有效期）

代码里由 `SMS_TEMPLATE_PARAM_COUNT` 控制（默认 1），**不写死**。

### 3. 返回体有两层错误，只看一层会漏

| 层 | 位置 | SDK 行为 |
|---|---|---|
| 顶层 | `Response.Error`（密钥错、模板不存在、签名没审过） | **会抛异常** |
| 逐条 | `SendStatusSet[].Code`（限流、模板不符…） | **不抛**，必须自己看 |

代码已两层都查（`packages/server/src/lib/sms.ts` 的 `assertSendSucceeded`），
失败返回 502 并把腾讯云错误码记进服务端日志。

## 三、填到服务器 .env（你自己在终端跑）

> ⚠️ **不要在 Claude Code 里跑** —— 密钥不该经过会记录它们的工具。
> 在**普通 PowerShell** 里执行：

```bash
ssh tencent "cd /home/ubuntu/dreamcity-platform && \
  sed -i '/^[[:space:]]*SMS_/d' .env && \
  cat >> .env <<'EOF'
SMS_DRIVER=tencent
SMS_APP_ID=1401230486
SMS_SECRET_ID=<你的子用户 SecretId>
SMS_SECRET_KEY=<你的子用户 SecretKey>
SMS_SIGN_NAME=深圳领航梦之城科技
SMS_TEMPLATE_CODE=2761496
SMS_TEMPLATE_PARAM_COUNT=2
SMS_CODE_TTL_MINUTES=5
EOF"
```

> **`sed -i` 那一行别省**：它先删掉所有旧的 `SMS_` 行再写新的。
> 少了这一步，如果 `.env` 里之前已经有 `SMS_*`，就会变成两份 ——
> 后面的覆盖前面的，于是「我改了怎么没生效」。
> （部署前的 `check-env.mjs` 也会拦这种重复，但那时已经晚了。）

写完先自检一遍（服务器上跑，Node 在）：

```bash
ssh tencent "cd /home/ubuntu/dreamcity-platform && node deploy/check-env.mjs .env"
```

看到 `✓ .env 配置检查通过` 再往下走。

然后重启 app 容器：

```bash
ssh tencent "cd /home/ubuntu/dreamcity-platform && sudo docker compose --env-file .env -f deploy/docker-compose.yml up -d app"
```

验收：

```bash
# 1. 健康检查
curl.exe https://platform.lhdreamcity.com/api/health

# 2. 用真手机号在家长端点「获取验证码」，看短信到不到
# 3. 看日志（失败时这里有腾讯云的原始错误码）
ssh tencent "docker logs --tail 50 dreamcity-platform | grep 短信发送失败"
```

> 注意：这一节要求**新代码已经上线**（compose 里才会透传 `SMS_*` 进去）。
> 部署通道没打通之前，容器里读不到这些变量，服务端会拒绝启动。
> 顺序见 [`../进展记录.md`](../进展记录.md) 的「还差什么」。

## 四、启动自检的两档行为

| `SMS_DRIVER` | 行为 |
|---|---|
| `log`（默认） | 只警告，服务正常起。验证码进服务端日志，是 `00000` |
| `tencent` 但配置缺项 | **拒绝启动**，并逐项点名缺哪个 |
| `tencent` 且配置齐全 | 正常启动 |

理由：配了 tencent 却缺项时，服务能起来、家长却永远收不到短信，
问题会被拖到真实家长登录不了才暴露 —— 那时候已经约好了课。
缺项直接拒绝启动比「看起来正常」安全。

## 五、排错对照表

| 错误码 | 意思 | 怎么办 |
|---|---|---|
| `AuthFailure.SecretIdNotFound` | SecretId 不存在或写错 | 核对子用户密钥 |
| `AuthFailure.SignatureFailure` | SecretKey 不对 | 核对 SecretKey |
| `FailedOperation.SignatureIncorrectOrUnapproved` | 签名不存在/没审过/类型与模板不匹配 | 查签名类型是否与模板类型一致 |
| `FailedOperation.TemplateIncorrectOrUnapproved` | 模板不存在、没审过，或不属于这个应用 | 查模板所属应用与 SDKAppID 是否一致 |
| `FailedOperation.TemplateParameterError` | 模板参数个数不对 | 对照模板里的 `{1}{2}` 数量调 `SMS_TEMPLATE_PARAM_COUNT` |
| `LimitExceeded.PhoneNumberDailyLimit` | 该号码当天发送量超上限 | 腾讯云默认 300 条/天 |

日志位置：`docker logs --tail 50 dreamcity-platform | grep 短信发送失败`
（错误码与脱敏后的手机号都在里面，前端只显示「验证码没发出去，稍等一会儿再试」）

## 六、频率限制：卡住时先分清是谁的闸

| 谁 | 限制 |
|---|---|
| **腾讯云** | 同一 IP 每分钟 100 条；单号码每分钟 10 条、每小时 100 条、每天 300 条 |
| **我们的代码** | 同一 IP 每小时 `SMS_IP_HOURLY_LIMIT`（默认 300）；同一号码每小时 `SMS_PHONE_HOURLY_LIMIT`（默认 5）；同号码两次发送间隔 `SMS_RATE_LIMIT_SECONDS`（默认 60 秒） |

一个教室的家长共用同一个公网出口 IP，所以 IP 额度要够一整个学校用。
腾讯云那边 100 条/分钟远宽于我们的 300 条/小时 —— **被卡住通常是我们自己的闸**，
改 `SMS_IP_HOURLY_LIMIT` 即可，不需要在腾讯云提工单。

真要调高腾讯云侧的额度：控制台右上角 → 工单，说明用途与峰值 QPS。
