# 活动插件规范

给教研看的。写完一个活动，研发不用介入就能上架。

---

## 一句话

> **活动 = 一个独立单文件 HTML + 一份 manifest**，运行在驾驶舱的 iframe 里，
> 结果通过 `postMessage` 交给宿主，由宿主落库。

**活动永远不直连后端。** 它没有账号、没有身份、不知道现在是谁在玩。

---

## 五条硬约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | 单文件、零外部 CDN、零后端请求 | 教室断网也要能上；已备案域名不背境外资源合规风险 |
| 2 | 结果必须可序列化且符合 `result_schema` | 否则无法自动沉淀作品与测评数据 |
| 3 | 必须提供 `offline_fallback`（打印版任务单） | 设备故障时课堂不能停 |
| 4 | 作品回传必须带 `visibility`；不采集真实姓名、位置与设备指纹 | 默认 `VIS_L0`，由平台按授权逐级放开 |
| 5 | 支持 `prefers-reduced-motion`，移动端可降级 | 教室设备与家长手机性能参差 |

`npm run check:constraints` 的 **C3 / C4** 会自动检查第 1、3、5 条。

## manifest

放在 `activities/manifest.json` 的 `plugins` 数组里：

```json
{
  "id": "lemon-stand",
  "name": "柠檬水摊大作战",
  "version": "1.0.0",
  "lesson_refs": ["L1-10", "L1-13", "L2-10", "L3-13"],
  "mode_cards": ["MODE_M2", "MODE_M3"],
  "duration_min": 12,
  "entry": "lemon-stand.html",
  "standalone": true,
  "result_schema": {
    "score": "number",
    "final_price": "number",
    "profit": "number",
    "rounds": "number",
    "badges": "string[]",
    "task_completion": "number"
  },
  "artifact_fields": ["final_price", "profit", "badges"],
  "result_optional": ["task_completion"],
  "offline_fallback": "任务单 P10（打印版）：画出你的定价表并写出成本、售价、利润",
  "fallback_2d": true,
  "grades": ["GRADE_L1", "GRADE_L2", "GRADE_L3"]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 3–64 位小写字母/数字/连字符。全局唯一 |
| `lesson_refs` | 适配的课次，如 `L1-10`。留空表示通用 |
| `mode_cards` | 服务哪些模式卡（`MODE_M1`…`MODE_M6`） |
| `duration_min` | 建议时长（分钟） |
| `entry` | 相对 `activities/` 的 `.html` 路径 |
| `standalone` | 能否脱离宿主单独打开（招生演示用） |
| `result_schema` | 结果字段与类型：`number` / `string` / `boolean` / `string[]` / `object` |
| `artifact_fields` | 哪些字段落库成「作品」（家长能看到） |
| `result_optional` | 可选字段。缺失不算错；其余字段缺失则拒绝回传 |
| `offline_fallback` | 断网 / 设备故障时的兜底：打印版任务单编号 |

`mode_cards` 里 **不应出现 `MODE_M5` / `MODE_M6` 作为可被插件承担的部分** ——
这两张卡必须真人。

## 与宿主的三步

### 1. 握手：宿主注入上下文

iframe 加载完成后，宿主会发一条 `dreamcity:host:init`：

```js
{
  type: "dreamcity:host:init",
  sessionId: "ses_xxx",
  studentId: "stu_xxx",      // 全班共用大屏时为 null
  studentNickname: "小宇",
  activityId: "lemon-stand",
  level: "GRADE_L1",          // 用来开放不同难度
  origin: "https://..."
}
```

活动要监听它，拿到 `sessionId` 之后才允许回传。

```js
var session = { sessionId: null, studentId: null, ready: false };

window.addEventListener("message", function (e) {
  if (!e.data || e.data.type !== "dreamcity:host:init") return;
  session.sessionId = e.data.sessionId;
  session.studentId = e.data.studentId || null;
  session.level = e.data.level || null;
  session.ready = true;
});
```

### 2. 回传结果

```js
parent.postMessage({
  type: "dreamcity:activity:result",
  activityId: "lemon-stand",
  sessionId: session.sessionId,
  studentId: session.studentId,
  payload: {
    score: 86,
    final_price: 6,
    profit: 42,
    rounds: 5,
    badges: ["定价小能手"],
    task_completion: 0.8
  },
  visibility: "VIS_L0",   // 默认私密，由平台按授权逐级放开
  ts: Date.now()
}, "*");
```

宿主会：
1. 校验 `activityId` 命中本次 session 的编排（不命中 → 404）
2. 按 `result_schema` 校验 payload（不符合 → 400）
3. 写 `session_record`
4. 按 `artifact_fields` 生成 `artifact` + `showcase`

**断网时**：宿主落库失败会把它存进本地队列，网络恢复后自动补传。
活动本身完全不需要感知这件事 —— 它只管 `postMessage`。

### 3. 单独打开（可选）

```js
if (window.parent === window) { session.ready = true; }
```

这样活动在招生演示页也能自己跑起来。

## 写活动的几条经验

这些是从已有三个活动里总结的，不是规定：

- **先成立为游戏，再挂教学含义** —— 「定价模拟器」是图表，「柠檬水摊」才是游戏。
  差距不在功能，在画面、角色、操作循环、反馈。
- **90 秒一轮** —— 课堂里一节实操 35–40 分钟，一个活动撑 10–15 分钟是上限。
  太长孩子会腻，太短没沉浸感。
- **要即时反馈** —— 结算画面、徽章、连击、彩带。孩子的成就感当场就发。
- **错误反馈用正向引导** —— 不用红叉。吉祥物永远是鼓励的表情（硬约束 C12）。
- **2D Canvas 足够** —— 投屏机常是集显甚至被关硬件加速。
  设备确定性 > 性能上限（硬约束 C3/C4）。
- **变量权限按级别开放** —— 变量实验室的做法：L1 只给一个变量，L2 两个，L3 三个并追问「相关 ≠ 因果」。
- **给 `offline_fallback` 写一句人话** —— 「任务单 P10（打印版）：画出你的定价表并写出成本、售价、利润」，
  比「见教案」有用得多。

|---|---|---|---|
| 柠檬水摊大作战 | `activities/lemon-stand.html` | L1-10 / L1-13 / L2-10 / L3-13 | 定价、成本、利润、甜蜜点 |
| 提示词闯关 | `activities/prompt-quest.html` | L1-04 / L2-04 / L3-03 | 角色 · 任务 · 格式 三段式 |
| 太阳系变量实验室（2D） | `activities/var-lab-2d.html` | L1-02 / L2-01 / L3-01 | 导入 → 预测 → 实验 → 记录 → 收尾 |

> 太阳系变量实验室的 3D 版用**同一份 manifest** 接入即可，平台侧不需要改。
> 3D 版不在 V1 范围（投屏机风险 + 教学价值需要实机验证）。

## 上架流程

```bash
# 1. 把 HTML 放进 activities/
# 2. 在 activities/manifest.json 的 plugins 里加一条
# 3. 重新入库（manifest 会同步进数据库）
npm run seed
```

或者走接口：

```bash
curl -X POST http://127.0.0.1:8787/api/plugins \
  -H "Authorization: Bearer <讲师token>" \
  -H "Content-Type: application/json" \
  -d @manifest.json
```

manifest 没通过校验会返回 400 与逐条的 `issues`，照着改就行。
